# Elsafe UI findings 1–4 implementation plan

> Execution: implement inline; regression tests before behavior changes, followed by a final review.

**Goal:** Correct the four UI findings approved by the user without changing the reporting or authentication workflow.

**Architecture:** Retain Flutter Material, existing screens, permissions and service calls. Use the existing theme extensions for form surfaces and text. Extract presentation-only responsive navigation and filter layouts so their behavior can be tested without a backend.

**Tech stack:** Flutter/Dart; existing flutter_test and http test helpers. No new packages.

**Spec:** The user approved UI review findings 1–4 in this conversation. Findings 5–6 (dashboard priorities and login workflow) are explicitly deferred.

## Constraints and design

- Keep all current login actions, labels and OAuth behavior.
- Keep dashboard content, role permissions, report fields, validations and save operations.
- Light/dark themes cover create/edit forms, their date dialogs, map picker chrome, photo picker and type sheet; preserve white text on solid colored actions.
- Filters wrap into two columns on phones, with full-width fields on very narrow layouts and readable labels/touch targets.
- Finding cards wrap badges, show descriptions on their own line and retain detail/edit/delete actions.
- Map Open, On Progress, Closed and legacy Close explicitly; missing/unknown values must never appear as successfully closed.
- Constrain the full login flow to 440 logical pixels, including dividers and secondary actions.
- Use a 224-pixel sidebar at widths >= 1024 and bottom navigation below that; preserve tab content across resizing, badge counts, drawer access and the FAB.
- Work in the existing workspace on a task branch; preserve pre-existing user edits in documents and graphify output.

## Review focus

- 320/375-pixel screens, large text, long owner/location names and all badges: no overflow.
- Theme changes must keep inputs, disabled fields, dialogs and validation legible.
- Null and unrecognized statuses stay neutral; Close retains compatibility with Closed.
- Resizing must preserve state and navigation callbacks and leave the FAB above mobile navigation.
- Admin permissions, guide/export destinations and notification badge behavior remain intact.
